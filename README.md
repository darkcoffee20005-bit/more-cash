# مور كاش — كاشير الكوفي شوب

نظام نقاط بيع وإدارة مصمم للكوفي شوب، على نهج Loyverse في سهولة الاستخدام، ومبني بـ **JavaScript (Node.js) + MongoDB**.
واجهة عربية RTL بألوان أخضر المقاهي والذهبي، تعمل على التابلت والكمبيوتر والهاتف من المتصفح.

## ماذا يفعل

| القسم | الوظائف |
|---|---|
| **البيع** | شبكة أصناف ملونة بالتصنيفات وبحث وSKU، أحجام (وسط/كبير)، إضافات (نوع الحليب إلزامي، نكهات، شوت إضافي)، ملاحظة للباريستا، دمج الأصناف المتطابقة، خصومات على الصنف أو الطلب، نوع الطلب (محلي/سفري/توصيل)، ربط عميل |
| **الدفع** | نقد مع أزرار مبالغ سريعة وحساب الباقي، بطاقة، زين كاش، FIB، **دفع مقسّم** بأكثر من طريقة، إيصال 80 مم |
| **التذاكر المفتوحة** | حفظ طلبات الطاولات وتعديلها لاحقاً، مع منع تعارض التعديل من جهازين |
| **شاشة التحضير** | الطلبات تظهر للباريستا فور الدفع: جديد ← قيد التحضير ← جاهز ← سُلّم، وتلوين المتأخر |
| **الإيصالات** | بحث برقم الإيصال أو العميل، إعادة طباعة، **استرجاع كلي أو جزئي** مع إعادة للمخزون |
| **الوردية** | رصيد افتتاحي، إدخال وسحب نقد بسبب، النقد المتوقع لحظياً، إغلاق بالعدّ الفعلي وتسجيل الفرق |
| **العملاء والولاء** | سجل العملاء، الزيارات والإنفاق، نقاط (نسبة قابلة للتعديل) واستبدالها كخصم |
| **المخزون** | المكونات (بن بالغرام، حليب بالمل، أكواب) تُخصم تلقائياً من **وصفة كل مشروب**، استلام بالمتوسط المرجح للتكلفة، هدر، جرد، سجل حركات، تنبيه حد أدنى |
| **التقارير** | ملخص (إجمالي، مرتجعات، خصومات، صافي، تكلفة، ربح، هامش)، حسب الصنف/التصنيف/الموظف/طريقة الدفع/الإضافات/الخصومات/نوع الطلب/اليوم، تصدير CSV |
| **المتابعة** | مبيعات اليوم مقارنة بالأمس، حسب الساعة، آخر 7 أيام، الأكثر مبيعاً، تنبيهات المخزون |
| **الموظفون** | دخول برمز PIN، أربعة أدوار: مالك، مدير، كاشير، باريستا |
| **الإعدادات** | بيانات المقهى والإيصال، الضريبة (بلا/مضافة/مشمولة)، طرق الدفع، أنواع الطلب، الولاء، تفعيل شاشة التحضير والتذاكر |

## التشغيل السريع (تجربة دون MongoDB)

```bash
npm start            # يعمل فوراً بتخزين ملف محلي data/dev-db.json
```
افتح `http://localhost:3000` واتبع شاشة الإعداد (اسم المقهى + رمزك + قائمة كوفي جاهزة).

> وضع الملف المحلي للتجربة فقط. للاستخدام الفعلي استعمل MongoDB كما يلي.

## التشغيل الفعلي مع MongoDB

### 1. المتطلبات
- **Node.js 20.10 أو أحدث** — [nodejs.org](https://nodejs.org)
- **MongoDB 6 أو 7** — إحدى الطريقتين:
  - على جهاز المحل: [MongoDB Community Server](https://www.mongodb.com/try/download/community) (Windows أو Ubuntu)
  - سحابي: [MongoDB Atlas](https://www.mongodb.com/atlas) (يوجد مستوى مجاني)

### 2. التثبيت
```bash
npm install                 # يثبت الاعتمادية الوحيدة: mongodb
cp .env.example .env        # ثم عدّل القيم
```

ملف `.env`:
```ini
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB=morecash
PORT=3000
PIN_PEPPER=اكتب-هنا-نصاً-عشوائياً-طويلاً-ولا-تغيره-لاحقاً
```

### 3. التشغيل
```bash
npm start
```
عند أول اتصال تُنشأ كل الفهارس تلقائياً، ثم تظهر شاشة الإعداد.

### 4. التابلت على شبكة المحل
الخادم يستمع على كل واجهات الشبكة. من التابلت (نفس الواي فاي) افتح:
`http://<عنوان-IP-للكمبيوتر>:3000` — مثل `http://192.168.1.10:3000`،
ثم من قائمة Chrome اختر **إضافة إلى الشاشة الرئيسية** ليفتح كتطبيق.
كل الأجهزة تعمل على نفس البيانات (طلبات التذاكر، شاشة التحضير، المخزون).

### 5. التشغيل الدائم
- **Windows**: `npm install -g pm2 pm2-windows-startup` ثم `pm2 start server/index.js --name morecash` و`pm2 save` و`pm2-startup install`.
- **Linux**: خدمة systemd بسيطة (`ExecStart=/usr/bin/node /opt/morecash/server/index.js` و`WorkingDirectory=/opt/morecash`).

### 6. النسخ الاحتياطي
```bash
mongodump --uri="mongodb://127.0.0.1:27017" --db=morecash --out=backup/$(date +%F)
mongorestore --uri="..." --db=morecash backup/2026-10-14/morecash   # الاستعادة
```
جدولها يومياً، واحتفظ بنسخة خارج جهاز المحل. Atlas يأخذ نسخاً تلقائية.

### 7. النشر على Vercel (عبر الإنترنت)
المشروع جاهز لـ Vercel: الواجهة ملفات ثابتة، والـ API دالة واحدة (`api/index.js`) تتصل بـ MongoDB Atlas.

1. أنشئ قاعدة مجانية على [MongoDB Atlas](https://www.mongodb.com/atlas)، وفي **Network Access** اسمح بـ `0.0.0.0/0` (لأن عناوين Vercel متغيرة)، وانسخ رابط الاتصال.
2. ارفع المشروع على GitHub، ثم في [vercel.com/new](https://vercel.com/new) اختر المستودع واضغط **Import** (الإعدادات تُقرأ من `vercel.json`).
3. في **Settings → Environment Variables** أضف:
   - `MONGODB_URI` = رابط Atlas
   - `MONGODB_DB` = `morecash`
   - `PIN_PEPPER` = نص عشوائي طويل (لا تغيّره بعد الإعداد)
4. **Redeploy**. افتح الرابط وأكمل شاشة الإعداد. كل دفع جديد إلى GitHub يُنشر تلقائياً.

النسخة التجريبية (بلا قاعدة بيانات) متاحة على نفس النشر في `/demo.html`.
للتجربة محلياً كما على Vercel: `node scripts/build_vercel.mjs && MORECASH_ALLOW_MEMORY=1 node scripts/vercel_dev.mjs`.

### 8. خلف وكيل عكسي على خادمك (اختياري)
ضع الخادم خلف nginx أو Caddy مع HTTPS، وأضف إلى `.env`:
`COOKIE_SECURE=true` و`TRUST_PROXY=true`.

## رموز الدخول والأدوار

| الدور | يستطيع |
|---|---|
| المالك | كل شيء |
| المدير | كل شيء عدا الموظفين والإعدادات (يسترجع، يطبق الخصومات المقيدة، يسحب نقداً) |
| الكاشير | البيع، التذاكر، الخصومات العادية، فتح وإغلاق الوردية، العملاء، الإيصالات |
| الباريستا | شاشة التحضير والإيصالات |

الصلاحيات تُفرض على الخادم؛ إخفاء الأزرار في الواجهة للراحة فقط.
الرمز من 4 إلى 6 أرقام، فريد لكل موظف، وبعد 5 محاولات خاطئة يُقفل الجهاز دقيقة.

## الدقة المالية

- كل المبالغ **دنانير صحيحة** — لا كسور ولا `double`. النسب بـ basis points (1000 = 10%)، والتقريب نصف لأعلى.
- **الخادم يعيد حساب كل فاتورة** من أسعار قاعدة البيانات بنفس الكود (`shared/calc.js`) ويرفض الطلب إن اختلف إجماليه عن الجهاز.
- خصم الطلب يوزَّع على الأصناف بطريقة الباقي الأكبر، فيبقى مجموع الأسطر مساوياً للإجمالي تماماً، وتصح أرباح كل صنف.
- **لا تكرار**: لكل عملية (بيع، استرجاع، حركة نقد، تعديل مخزون) معرّف فريد؛ إعادة الإرسال بعد انقطاع تعيد نفس النتيجة دون أثر جديد.
- الاسترجاع يُحجز ذرياً فلا يتجاوز المتبقي حتى مع جهازين في نفس اللحظة؛ آخر جزء مسترجع يأخذ الباقي الدقيق.
- المخزون دفتر حركات بمفتاح فريد لكل حركة، والرصيد قابل للمطابقة مع الدفتر من شاشة المخزون.
- إن انقطعت الكهرباء أثناء تسجيل بيع، تُستكمل آثاره (المخزون والنقاط) عند تشغيل الخادم.

## البنية

```
server/
  index.js          التشغيل وقراءة .env
  http.js           خادم HTTP بلا إطار: ملفات الواجهة، الكوكي، CSRF، ترويسات الأمان
  db/connect.js     MongoDB (الإنتاج) أو تخزين ملف (التجربة)
  db/indexes.js     الفهارس والقيود الفريدة
  db/memory.js      بديل في الذاكرة يطابق واجهة driver MongoDB (للاختبار والتجربة)
  app/              الخدمات: auth, catalog, sales, shifts, inventory, reports, seed — وواجهة API في index.js
shared/             يعمل في الخادم والمتصفح: الحسابات، التقارير، الصلاحيات، التنسيق
public/             الواجهة (SPA بلا مكتبات): js/views/{pos,receipts,ops,admin}.js و css/app.css
demo/               نسخة تجريبية تعمل كلياً في المتصفح بنفس كود الخادم
tests/              اختبارات node:test + فحص متصفح حقيقي
```

## الاختبارات

```bash
npm test                          # 15 مجموعة: الحسابات، قاعدة البيانات، تدفقات API كاملة، HTTP، الواجهة
node tests/browser/smoke.mjs      # متصفح حقيقي (يتطلب playwright): دورة بيع كاملة بالنقر + صور

```

## حدود معروفة

- **لم يُختبر هنا على خادم MongoDB حقيقي**: بيئة البناء لم تستطع تنزيل MongoDB ولا حزمة `mongodb`. كل الاختبارات تعمل على بديل يطابق واجهة الـ driver الرسمي v6، والكود يستخدم عمليات MongoDB قياسية فقط (بلا معاملات ولا aggregate). شغّل `npm test` ثم جرّب دورة بيع بعد `npm install` مع `MONGODB_URI` عند أول تثبيت.
- `package-lock.json` غير مرفق للسبب نفسه؛ يُنشأ عند أول `npm install` — احتفظ به.
- على Vercel: تحديد محاولات الرمز الخاطئ يعمل لكل نسخة من الدالة على حدة، والطلبات تمر عبر الإنترنت؛ للمحل يبقى الخادم المحلي أسرع.
- يتطلب اتصالاً بالخادم: إن انقطعت شبكة المحل عن الخادم يتوقف البيع (لا يوجد وضع أوفلاين في هذا الإصدار). تشغيل الخادم على جهاز داخل المحل يجعل الإنترنت غير ضروري.
- الطباعة عبر نافذة الطباعة في المتصفح (طابعة 80 مم مثبتة على الجهاز)؛ لا طباعة ESC/POS مباشرة ولا فتح درج النقد آلياً.
- الإضافات لا تخصم من المخزون (اختيار حليب الشوفان لا يخصم من مخزون الشوفان) — الوصفة لكل حجم فقط.
- استرجاع مشروب محضّر لا يعيد مكوناته للمخزون؛ يُعاد فقط الصنف الجاهز (كرواسون، ماء) عند اختيار ذلك.
- النقاط المستبدلة لا تُعاد للعميل عند الاسترجاع؛ النقاط المكتسبة تُخصم بالتناسب.
- فرع واحد ودرج نقد واحد (وردية مفتوحة واحدة في وقت واحد).
